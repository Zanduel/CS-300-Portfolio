# CS-300-Portfolio
Portfolio artifacts and reflections from SNHU CS 300: Data Structures and Algorithms.

## What was the problem you were solving in the projects for this course?

I was trying to determine which data structure best fit the company's needs. I compared different data structures to find one that could efficiently store, search, and organize course information for the advising program.

## How did you approach the problem, and why do you think understanding data structures is important?

When approaching the problem, I analyzed each data structure to see which would perform best in terms of runtime, memory use, and the required output. Understanding data structures is important because different structures have different strengths and weaknesses. A company's requirements can determine which data structure best fits the problem.

## How did you overcome any roadblocks you encountered while going through the activities or project?

The main roadblock I encountered came after I submitted Project Two, when my professor told me he couldn't compile it. I investigated the problem and realized my program still depended on the university-provided CSV parser. I removed that dependency and changed the program to use standard C++ file handling so the source file could compile and run independently. This experience taught me the importance of testing a program outside of the development environment before submitting it.

## How has your work on this project expanded your approach to designing software and developing programs?

My work on these projects expanded my approach to software design by teaching me not to treat different data structures as the same. Each data structure performs differently depending on the problem and the results needed. Instead of immediately choosing one structure, I learned to explore options and compare their strengths and weaknesses. This helps me choose the structure that best matches the user's or company's needs.

## How has your work on this project evolved the way you write programs that are maintainable, readable, and adaptable?

My work on these projects encouraged me to stay open and flexible when writing programs so I can better meet others' demands and needs. I learned that readable, maintainable code makes it easier to understand how a program works and to make changes as requirements change. Keeping the program organized also makes it easier to adapt the code instead of rebuilding everything from scratch.
